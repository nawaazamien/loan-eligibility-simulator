# Decisions

Short decision records. Each one notes where the requirement came from: **Employer** (the assignment brief), **Design** (the imported Claude Design project) or **Implementation** (a choice made here).

| ID    | Decision                                                                                                                                                                                                                                                                                                                                                                                                              | Source                                                                                             | Reason                                                                                                                                                                                                                                                                           |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Build the customer-facing screen from `LoanSimulator.dc.html`. Treat `Loan Simulator Board.dc.html` as a presentation board and do not ship it.                                                                                                                                                                                                                                                                       | Design / Implementation                                                                            | The board only arranges preset artboards of the one live component, plus notes for the design tool.                                                                                                                                                                              |
| D-002 | Collect existing debt repayments and the term in addition to income, expenses and loan amount.                                                                                                                                                                                                                                                                                                                        | Design                                                                                             | The employer's three inputs are a subset. Debt makes the affordability rule meaningful, and the term drives the repayment.                                                                                                                                                       |
| D-003 | React 19.3, Vite 8.3, TypeScript 6.0 (strict), Vitest 5, Testing Library 16, Playwright 1.64, ESLint 10 with typescript-eslint 8, Prettier 3. Exact versions are pinned and the lockfile is committed.                                                                                                                                                                                                                | Employer (React, tests) / Implementation (versions)                                                | These were the current stable releases on 2026-10-19. The handoff names React 18, but nothing in the design depends on 18, and 19 is the supported line. **TypeScript 7.0 was not used:** typescript-eslint 8.71 declares `typescript <6.1.0`, so TypeScript is pinned at 6.0.3. |
| D-004 | Folders: `src/app` (page composition), `src/components` (generic presentational pieces: header, footer, Frame), `src/features/loan-simulator` (simulator UI, and in Phase 2 its pure model in `model/`), `src/styles` (tokens and global CSS).                                                                                                                                                                        | Employer (suggested layout) / Implementation                                                       | Keeps calculations beside their feature but out of components. The handoff's `src/lib` + `src/state` split was not adopted, to avoid an extra layer for a single feature. Empty folders were not created.                                                                        |
| D-005 | Styling with CSS Modules plus one `tokens.css` of custom properties. Responsive behaviour uses a single mobile-first `@media (min-width: 760px)` that changes the layout tokens.                                                                                                                                                                                                                                      | Design (tokens, breakpoint) / Implementation (mechanism)                                           | No component library is needed for native fields and cards. The reference measures container width with a ResizeObserver. For a full-page app the viewport media query is equivalent, needs no JavaScript and avoids layout flashes.                                             |
| D-006 | Docker: `node:24.18.0-alpine` build stage, then `nginxinc/nginx-unprivileged:1.29-alpine` runtime, running as uid 101 on port **8080**.                                                                                                                                                                                                                                                                               | Employer (Dockerfile) / Implementation                                                             | A non-root runtime cannot bind port 80, so the handoff's `-p 8080:80` becomes `-p 8080:8080`. The runtime holds only static files.                                                                                                                                               |
| D-007 | Caching: `/assets/*` (content-hashed) gets `max-age=31536000, immutable`. Everything else, including `index.html`, gets `no-cache` (always revalidated). Unknown paths return 404 because the app has no client-side routes. A strict CSP (`'self'` only) and standard security headers are sent on every response.                                                                                                   | Employer (no stale index) / Implementation                                                         | New deploys are picked up immediately, while hashed assets stay cached. Self-hosted fonts make `font-src 'self'` possible.                                                                                                                                                       |
| D-008 | Money is handled in integer cents. The amortised instalment is rounded once, half-up, to cents. The affordability test is the exact integer inequality `5·repayment ≤ 2·available`.                                                                                                                                                                                                                                   | Employer (avoid floating-point boundary decisions) — **changes** Design ("round only for display") | It prevents results like R1 082.04 vs 40% of R2 705.10 flipping because of binary floating point, and the displayed repayment is exactly the figure that was compared. Visual output is unchanged. See SIMULATION_MODEL §4.                                                      |
| D-009 | "Total repayable" includes the monthly service fee (repayment × term).                                                                                                                                                                                                                                                                                                                                                | Design open question → Implementation                                                              | It matches the displayed repayment, which already includes the fee. The figure-note copy ("Includes the R69 monthly service fee") makes this explicit.                                                                                                                           |
| D-010 | No persistence (`localStorage`, `sessionStorage`, cookies), no analytics and no network calls with user input.                                                                                                                                                                                                                                                                                                        | Employer (no personal data) / Design (recommend no)                                                | Financial inputs are personal. The footer states that the app doesn't store your information.                                                                                                                                                                                    |
| D-011 | Fonts are self-hosted via `@fontsource` (Barlow 400/500/600, Barlow Condensed 600), Latin subset only.                                                                                                                                                                                                                                                                                                                | Design (recommended) / Implementation (subset)                                                     | Works offline and in Docker without Google Fonts, and allows a strict CSP. The Latin subset covers every glyph in the copy (NBSP, typographic quotes, dashes, U+2212).                                                                                                           |
| D-012 | Phase 0 panel bodies are explicit placeholders (dashed box, text naming the phase, `data-placeholder` attribute). The shell renders no sample figures.                                                                                                                                                                                                                                                                | Employer (no hardcoded results) / Implementation                                                   | It makes the temporary content unmistakable. A unit test asserts that no rand figure appears in the estimate panel before a calculation exists.                                                                                                                                  |
| D-013 | `design/reference/support.js` (the generated design-preview runtime) is kept locally for reference but git-ignored.                                                                                                                                                                                                                                                                                                   | Implementation                                                                                     | It is design tooling, not product code. It has no stated licence, so it is not redistributed in a public repository.                                                                                                                                                             |
| D-014 | Browser tests run against the **production** bundle: `vite preview` by default, or any URL via `E2E_BASE_URL` (used to test the Docker container).                                                                                                                                                                                                                                                                    | Employer (production-grade, Docker) / Implementation                                               | The dev server is never what users get. The same suite verifies both the preview build and the container.                                                                                                                                                                        |
| D-015 | Light theme only (`color-scheme: light`).                                                                                                                                                                                                                                                                                                                                                                             | Design                                                                                             | The design specifies no dark theme. Declaring light keeps native controls consistent with the tokens.                                                                                                                                                                            |
| D-016 | The repository licence is left unselected.                                                                                                                                                                                                                                                                                                                                                                            | Employer (owner's choice)                                                                          | Choosing a licence is the owner's decision.                                                                                                                                                                                                                                      |
| D-017 | Phase 1 adds two exact-pinned dependencies: `lucide-react` 1.52.0 (icons) and, for tests only, `@testing-library/user-event` 14.6.7.                                                                                                                                                                                                                                                                                  | Design (Lucide icons) / Implementation                                                             | The handoff names Lucide and user-event. Versions were the newest published at least two weeks before 2026-10-19. Icons are imported individually, so only the ones used are bundled. user-event gives real typing, Tab and arrow-key behaviour in component tests.              |
| D-018 | Until Phase 2, **Calculate estimate** is a native `disabled` submit button with a visible note ("Calculation isn't available in this development version yet.") linked by `aria-describedby`. The form's submit handler only prevents default, and Enter in a field cannot submit because the default button is disabled.                                                                                             | Employer (no fabricated results) / Implementation                                                  | The button must not be a clickable no-op, and no estimate may appear before the real calculation exists. Phase 2 removes the note and enables submission.                                                                                                                        |
| D-019 | When the loan text is empty, malformed or negative, the slider **keeps its last position** instead of jumping to R1 000 as the reference does. A valid amount still moves it (rounded to the R1 000 step, clamped to range).                                                                                                                                                                                          | Design → Implementation (deviation)                                                                | Clearing the field to type a new amount made the reference slider jump to the minimum and back. Keeping its place never invents an amount, and the text field stays the source of truth.                                                                                         |
| D-020 | Phase 1 shortens the example status message to "Example values added." The design's continuation, "Select Calculate estimate to see the result.", returns in Phase 2. The reset message is unchanged.                                                                                                                                                                                                                 | Design → Implementation (temporary)                                                                | It would point the customer at a disabled button.                                                                                                                                                                                                                                |
| D-021 | The amount parser (SIMULATION_MODEL §1) and blur formatting are introduced in Phase 1, in `model/amount.ts` and `model/format.ts`. Editable fields group digits with ordinary spaces (`28 500`, as in the reference values); display figures use NBSP (`R1 000`).                                                                                                                                                     | Design / Implementation                                                                            | Slider sync needs to know whether the loan text is a valid amount. Formatting only on blur keeps the caret still while typing. Ordinary spaces in fields copy and paste predictably; NBSP stops display figures breaking across lines.                                           |
| D-022 | On the selected term cell, the keyboard focus ring uses the text colour instead of the accent.                                                                                                                                                                                                                                                                                                                        | Design → Implementation (accessibility fix)                                                        | The reference draws an accent ring inset on an accent-filled cell, so focus on the selected term, which is where Tab lands, was invisible. The text colour on the accent fill is about 4:1, above the 3:1 needed for focus indicators. Unselected cells keep the accent ring.    |
| D-023 | Each amount label carries visually hidden text, "in rand" (for example "Monthly take-home income in rand"). The space sits outside the hidden span.                                                                                                                                                                                                                                                                   | Design (optional, HANDOFF §6) / Implementation                                                     | The visible "R" prefix is decorative and hidden from screen readers. With the space inside the span, Chromium and jsdom computed different names ("income , in rand" vs "incomein rand"); with it outside, both compute the same name.                                           |
| D-024 | The estimate panel keeps its blueprint frame positioned on mobile, so its corner marks stay on the panel.                                                                                                                                                                                                                                                                                                             | Design (intent) → Implementation                                                                   | Rendering the reference at 360 px showed its results panel set to `position: static`. Its absolutely positioned corner marks then escape to the page edges. That is a preview artefact, not the intended design (desktop and the form panel show the marks on the frame).        |
| D-025 | The form state is one pure reducer (`formState.ts`), owned by `LoanSimulator` and passed to `LoanForm`. The disclosure's open state is local to `AssumptionsDisclosure`. There is no global state library.                                                                                                                                                                                                            | Implementation                                                                                     | The estimate panel will need the same state in Phase 2, so it lives in their common parent. The reducer is unit-tested without React.                                                                                                                                            |
| D-026 | Result freshness is derived, not stored. The last successful calculation keeps a canonical key: the validated cents of each amount plus the term. On every render the current inputs are keyed the same way and compared. Invalid or empty text is keyed by its raw text, so it never matches. The result stays visible until the next successful calculation or Reset; "Use example values" only changes the inputs. | Design (stale behaviour) / Implementation                                                          | Formatting-only edits (`28500` ↔ `28 500`) keep the result current, any real change or invalid edit marks it out of date, and returning to the calculated values makes it current again. Every figure shown comes from the stored estimate, never from the live form.            |
| D-027 | Announcements: one visually hidden `aria-live="polite"` region outside the panel holds a short sentence per successful calculation, rendered as a new element each time (keyed by the calculation). The out-of-date banner is in a `role="status"` region that exists whenever a result exists. The phone-only "Calculate again" note under the form is hidden from 760 px with CSS and is **not** a live region.     | Design / Implementation                                                                            | An identical recalculation is still announced, exactly once, and a failed resubmission does not repeat the old announcement. Keeping the status region mounted makes the banner announce reliably. Making the phone note live as well would announce the same change twice.      |
| D-028 | When an estimate is above the limit by less than R1, the explanation shows the gap with cents ("R0.01 a month above it").                                                                                                                                                                                                                                                                                             | Design → Implementation (deviation)                                                                | The design's whole-rand format would say "R0 a month above it", contradicting the outcome (reference case 6). All other figures follow the design's rounding.                                                                                                                    |
| D-029 | An unsupported term is a programming error: `checkForm` throws a `RangeError` rather than showing a customer message.                                                                                                                                                                                                                                                                                                 | Implementation                                                                                     | The term can only come from five native radio buttons, so no customer can enter another value. Failing loudly protects the model from a bad caller without inventing copy for an impossible state.                                                                               |
| D-030 | After a calculation, focus moves to the estimate heading (`tabindex="-1"`, `preventScroll`), which is scrolled into view below 760 px, smoothly unless reduced motion is set. After a failed submit, focus moves to the error summary. Both show a focus ring for any focus, not only `:focus-visible`.                                                                                                               | Design / Implementation (deviation in the ring)                                                    | The reference only shows these rings for keyboard focus. After a mouse click Chromium does not treat scripted focus as focus-visible, so the moved focus would be invisible.                                                                                                     |
| D-031 | The Recalculate button is 44 px tall (the reference uses 40 px).                                                                                                                                                                                                                                                                                                                                                      | Design → Implementation (deviation)                                                                | It meets the handoff's own 44 px target-size guidance (HANDOFF §8).                                                                                                                                                                                                              |
| D-032 | Phase 1's temporary measures are removed: Calculate is enabled and its development note is gone (D-018), and the full example message is restored (D-020). The estimate does not compute or show a separate "total cost" figure.                                                                                                                                                                                      | Design / Implementation                                                                            | Calculation exists now. The design shows total repayable (fees included, D-009) but no total cost, so none is calculated.                                                                                                                                                        |
